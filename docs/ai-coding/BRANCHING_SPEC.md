# 分支管理与完整交付规范

本个人 GitHub 项目长期保留 `main`、`test`、`preprod`。分支承载集成与候选历史，实际运行环境仍由配置和发布流程选择；创建分支不代表已部署环境。

## 三条长期分支

| 分支 | 职责 | 保护规则 |
|---|---|---|
| `main` | 可构建、可测试的正式候选与发布基线 | 长期保留，不删除、不 force push |
| `test` | 完整功能的测试集成 | 长期保留，不删除、不 force push |
| `preprod` | 预发布候选与验收 | 长期保留，不删除、不 force push |

- 新增长期分支必须有明确用途和授权；不因公司仓库存在私有化分支而在个人仓库照建。
- 本轮建立缺失 test/preprod 时，以读回确认的最新 main 为起点；已有分支保留历史，不强推重建或覆盖。
- 分支保护设置与文档规则分别核对；没有查询远端设置时，不宣称已配置平台级保护。
- `dev`、`prod` 仍可作为运行环境名称，不因环境名自动创建同名长期分支。

## 新任务与功能分支

1. 核对仓库、当前分支、HEAD、dirty、其他会话及 worktree，再 fetch origin；只读查询无需创建分支。
2. 从最新 origin/main 的确定 SHA 创建一个目标的短分支；同一任务核对基线和归属后可复用原分支。用户明确指定其他基线时记录该次范围，不从混合 test/preprod 随意拉新功能。
3. 分支可使用 feature/、fix/、docs/、chore/、refactor/、test/、hotfix/、release/ 或本环境规定的 codex/ 前缀，名称使用小写字母、数字和短横线。
4. 分支承载完整功能，以及必要测试、文档、migration、契约、依赖和回滚说明，不混入无关工作。
5. 跨仓功能分别从各仓 main 建同主题分支，记录各仓固定 HEAD 和精确依赖；缺少必要配套不得称为正式就绪。

## 集成、候选与合入

- 经授权把完整功能合入 test 验证；按本批验收需要将确定候选进入 preprod。只进入 test/preprod 时保留功能源分支与验收证据。
- 正式候选由最新 main、完整功能及全部必要跨仓配套组成，完成候选本身的风险匹配验证后，整体 merge 或快进合入 main。
- 混合 test/preprod 的总测试通过不代替正式候选验证，不默认把整个集成分支合回 main；只有用户明确指定整条分支就是本批完整候选时才按范围交付。
- 常规功能不通过零散 cherry-pick 重新拼装。用户指定的历史补丁、紧急修复或纯规则同步可作为受控例外，先核对完整依赖并验证。
- 开工、提交前和推送前 fetch。远端 main 前进时同步到最新远端并重跑受影响验证；已共享历史不强推，冲突不靠覆盖他人文件解决。
- Review 可补充风险检查，不新设已授权合入的人工审批门禁；编译、测试、安全、契约和回滚验证仍须与风险匹配。

## CI、环境与发布

- GitHub Actions 的权威入口是本仓 `.github/workflows/`。外部流水线仅在存在并核实权威入口时记录，不复制公司 GitLab/Jenkins 或自动部署 lane。
- 当前配置和执行结果分别取证；分支存在不代表该分支触发 CI，更不代表已经部署。不要依据文档推断自动化能力。
- 会触发自动化的跨仓 push 按本批授权串行执行，前一项实际结束后再继续；本地只读检查和验证可以并行，不以 ci.skip 绕过既有检查。
- Git 合入、本地验证、远端 CI、制品发布、环境部署和真实业务验收分别报告；不能由前一层推定后一层。
- commit/push/merge、tag、制品发布、部署和回滚遵守当前用户授权范围；用户已经授权的同批动作继续完成，不重复索要确认，也不扩展到其他项目或环境。
- 正式版本、不可变 tag、精确制品和校验值按 VERSIONING_SPEC.md 记录；纯规范文档不升级业务版本或发布制品。

## 功能分支清理

满足以下条件后，按本批授权清理本任务短分支：

1. 完整功能与必要跨仓配套均已合入各自 main，main 已推送且远端读回一致。
2. 用最新远端 main 核对源分支完整包含关系，记录功能分支和 main 的固定 SHA；不能只凭名字、时间或部分提交等价判断。明确 squash/等价合并时需完整差异与验证证据。
3. 没有唯一未交付提交、他人 dirty、依赖或其他 worktree 占用。
4. 先逐个删除满足条件的远端短分支，再用普通 branch -d 删除本地短分支；最后 fetch --prune 并读回结果。远端本来不存在时明确记录，不把删除命令成功当作曾存在的证据。

- main/test/preprod 无论是否与 main 同 SHA 都不能删除、强推或按短分支清理。
- 只合入 test/preprod、未合入 main、用途不明、仍有唯一提交或其他 worktree 正在使用的分支必须保留；超期只提示复核，不自动删除。
- 用户明确要求废弃某分支时按精确授权处理，不能把“清理本轮已合分支”解释成清理所有分支。
- worktree 与分支分别管理。保留其他会话、dirty、用途不明、唯一未推送提交或仍在使用的 worktree；detached HEAD 不是删除理由，不用 branch -D 绕过占用保护。

## 交付回执

写明源分支和固定 HEAD、test/preprod/main 各自状态、跨仓精确依赖、验证结果、推送与 CI、部署及未验收事项、分支清理或保留原因。历史 archive 和旧交付记录保留当时事实，现行规则以本文件和 AGENTS.md 为准。
